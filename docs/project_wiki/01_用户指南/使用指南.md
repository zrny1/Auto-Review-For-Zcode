# 使用指南

## 审查对话框（默认关闭，重要说明）

插件的**自有审查对话框默认是关闭的**（`dialog_on_ask: false`）。

- **关闭时（默认）**：ask 决策走 ZCode 客户端**原生审批流程**（本地弹原生审批框，远程控制时请求可达手机）。
  原生框对审查分析的显示与权限模式有关（经客户端 3.12.3 逆向确认）：**自动编辑模式下走"升级路径"，
  审查分析（reason）会随审批请求送达原生框与远程端**；default 模式下客户端"同向叠加"会丢弃
  hook 文案，原生框不显示分析。审查结论始终完整记录在 `review.log` 并事后转述给主 agent。
- **开启时**（`/auto-review set dialog_on_ask true` 或图形界面勾选）：ask 决策弹出插件的深色审查对话框，
  展示完整分析（风险徽章 + 命令 + 分析/风险点/影响范围），你的点击直接决定放行/阻断。三个按钮：
  - **允许执行**：本次放行（下次同指令仍会审查）；
  - **本次会话允许**：放行且同一指令在本对话内**不再询问**（精确匹配整条指令；新增的 deny/ask 危险规则
    仍优先生效；跨会话或超 24 小时自动失效，`/auto-review session list|clear` 可查看与清空）；
  - **拒 绝**：阻断（关闭窗口均等同拒绝）。
  键盘操作：**左右方向键**移动按钮光标（白框，初始在「拒 绝」），**回车**点击光标所在按钮，**Esc** = 拒绝。
  对话框**不会自动消失**（关闭窗口=拒绝）；注意它是主机本地窗口，**远程控制（手机）场景看不到**，
  远程前请保持关闭。

## 图形配置界面

```
/auto-review gui
```

打开深色主题设置窗口（与审查对话框同风格），可视化配置：

- **开关**：启用自动审查 / 审查对话框
- **审查范围**：Bash / Write / Edit 勾选；「脚本内容随命令送审」勾选 + 单文件字节上限
  （开启后 python/node/bash 等调用的脚本文件内容随载荷一并送审）
- **模型**：provider 下拉（来自 ZCode 配置的多源合并：`~/.zcode/v2/provider_config.json`
  优先、`~/.zcode/v2/config.json` 与旧版 cli 布局兜底；优先显示 provider 名称、无名称才显示 ID，
  含"跟随主 agent"）、模型下拉、fallback provider/模型（主 provider 不可用时自动切换）、超时与缓存
- **危险规则**：列表展示、添加（正则即时校验）、删除、命中测试、恢复出厂
- **安全策略提示词**：「打开提示词编辑器」进入独立编辑窗口——显示当前全文、就地修改、
  恢复出厂内容；保存时校验输出契约字段（decision/risk_level/analysis/risks/scope
  缺失会警告确认），保存后立即生效（每次审查前现读文件）

点击「保存」写入配置即时生效；所有能力与命令式配置完全等价，按习惯选用。

## /auto-review —— 总控

| 用法 | 效果 |
|------|------|
| `/auto-review` | 查看状态：开关、审查工具、provider/model、规则条数、提示词是否自定义 |
| `/auto-review on` / `off` | 开启 / 关闭自动审查 |
| `/auto-review set <key> <value>` | 修改配置 |

常用配置项：

```
/auto-review set model glm-5.3-flash        # 换快模型降延迟（示例为 flash 级模型名）
/auto-review set provider <provider名>       # 安全子agent 用与主 agent 不同的 provider
/auto-review set fallback_provider <provider名>   # 主 provider 不可用（超时/HTTP 429 限额/缺密钥等）时自动切换的备用 provider
/auto-review set fallback_model <模型名>          # fallback 指定模型（留空用该 provider 第一个模型）
/auto-review set review_tools '["Bash","Write"]'  # 扩大审查范围到文件写入
/auto-review set cache_ttl_seconds 7200     # 延长缓存有效期
/auto-review set inspect_scripts true       # 开启脚本内容随命令送审（默认关）
/auto-review set script_max_bytes 32000     # 脚本送审单文件读取上限（默认 16000）
```

## /danger-rules —— 危险规则（不经过安全子 agent）

规则是本地正则，按数组顺序匹配，**首个命中生效**。三种动作：

- `deny`：直接拦截
- `ask`：转人工审查
- `allow`：白名单直接放行（跳过 LLM，用于高频安全命令提速）

```
/danger-rules                                            # 查看全部规则
/danger-rules test 'git push origin main --force'        # 先测一条规则是否会命中
/danger-rules add deny 'drop\s+database\b' '删库不可恢复'  # 加规则（正则用单引号包裹）
/danger-rules add allow '^git\s+status\b' 'git status 白名单'
/danger-rules remove 3                                   # 按序号删规则
```

也可以直接说人话，例如"帮我加一条规则：所有 docker 命令都要转人工"——主 agent 会转写正则、
先 test 验证再落盘。出厂自带 14 条高危规则（rm -rf 根目录、格式化、fork 炸弹、强推、
管道执行远程脚本、注册表写入、sudo 提权等）。

## /security-prompt —— 审查策略调优

```
/security-prompt                # 查看当前提示词全文
/security-prompt edit 审查更严格一些，任何网络请求都转人工   # 按自然语言要求改写
/security-prompt reset          # 恢复出厂默认
```

图形化方式：`/auto-review gui` → 「打开提示词编辑器」，全文显示、就地编辑、
恢复出厂、保存即生效（保存时自动校验输出契约字段）。

改写立即生效（每次审查前现读文件）。**输出契约段的 JSON 字段名不可改**，
否则所有审查会解析失败兜底转人工（命令与 GUI 编辑器都会自动保护该段）。

## 审查日志

`~/.zcode/auto-review/review.log` 每行一条决策，标注来源层：

```
[2026-08-29T08:00:01Z][INFO][rule] deny Bash: rm -rf / (命中危险规则...)
[2026-08-29T08:00:05Z][INFO][llm]  allow risk=low 2.5s
[2026-09-05T08:00:07Z][INFO][script] 脚本送审 1 个文件: deploy.py   # 开启脚本送审后
[2026-08-29T08:00:09Z][WARN][fallback] 审查失败转人工: HTTP 401: ...
```

排查插件行为先看这里；hook 层面的执行记录（触发/超时/阻断）另见 ZCode 日志。

## 推荐搭配

1. 权限模式：**自动编辑模式**（自动审查的设计基座）
2. 高频安全命令加 `allow` 白名单（几乎零延迟）
3. 明确不可碰的命令加 `deny` 规则（确定性拦截）
4. provider 用 API Key 型；审查模型选 flash 级
