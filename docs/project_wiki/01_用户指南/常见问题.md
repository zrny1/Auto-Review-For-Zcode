# 常见问题

## 远程控制（手机操作主机）时看不到审查对话框怎么办？

子 agent 的审查对话框是主机本地窗口，手机上无法弹出；且当前版本客户端未向 hook
提供任何远程会话标记（已核查 hook 输入字段、数据表、querySource 枚举），无法自动检测。
**远程前请先关闭对话框**（审批自动回落客户端原生流程，请求可达手机）：

```
/auto-review set dialog_on_ask false
```

回到主机后 `/auto-review set dialog_on_ask true` 恢复。
（插件已预留信号检测：未来客户端若在 hook 输入中提供 querySource/remote 标记，将自动跳过对话框。）

## 审查对话框会自动消失吗？

不会。对话框一直保留直到你点击「允许执行」或「拒绝」；直接关闭窗口按**拒绝**处理，
绝不静默放行或回落默认审批。仅当对话框基础设施故障（如 PowerShell 不可用）才回落
客户端原生审批框。

## 审批框有时显示审查分析、有时不显示？

取决于命令在权限模式下的"原有决策"：
- 命令被模式判为**低风险**（如 ls 等只读命令，模式本会直接放行）时，hook 的 ask 属于
  "放行→升级人工"，审批框**会显示** hook 的分析（升级路径携带 reason）；
- 命令被判**有副作用**（如 rm/node/curl，模式本就要询问）时，hook 的 ask 属于同向叠加，
  客户端沿用原决策、**不渲染** hook 分析。
这是客户端合并逻辑的边界。插件的兜底：ask 决策会同时通过 additionalContext 把分析送进
主 agent 上下文（主 agent 会向你转述）；deny 场景分析必然显示。

## allow 白名单会放行复合命令（如 "ls; rm -rf x"）吗？

不会（v0.1.3 起）。复合命令按顶层分隔符（`;` `&&` `||` `|` 换行，引号与 $() 内不切分）
拆段逐段过规则：任一段命中 deny/ask 即整体生效；**全部段命中 allow 才放行**；
存在未覆盖段则整体降级 LLM 审查。allow 规则也不再命中复合命令的全文。

## 审查报"响应中没有文本内容"或经常超时？

GLM 系模型是混合推理模型，默认深度思考会拖慢响应并可能耗尽 token 额度导致正文为空。
v0.1.2 起插件已在 anthropic 协议显式关闭 thinking（实测 16s→3~5s，正文稳定）。
若仍出现：确认审查模型是 flash 级（`/auto-review set model glm-5.3-flash`）；
若插件版本较旧，更新插件。此场景兜底行为是转人工，不会放行。

## 弹的审批框只有"安全审查不可用"，没有分析/风险点/影响范围？

说明该次 LLM 审查失败（超时/网络/输出异常），插件按设计转人工且**不编造分析**。
修好 LLM 链路（见上一条）后即可看到完整三段式警告。

## 添加市场源或安装时弹"Claude marketplace refresh timed out after 30 seconds"？

**不影响本地插件的安装与使用。** 该超时只属于官方市场源（`claude-plugins-official`，
界面品牌名"Claude marketplace"）的后台联网刷新——客户端源码中此 30s 定时器仅对官方市场挂载，
本地市场源根本不经过这段代码。官方源刷新失败只影响官方插件列表的发现/更新。
处理：打开 已安装 标签确认 auto-review 已装好即可；没装上就对它再点一次 Get（本地安装不走网络）。
官方源刷新慢可按官方文档设置 `ZCODE_HTTP_PROXY`，但非必需。

## 装了插件，命令还是会直接弹审批框？

检查三点：
1. `/auto-review` 看开关是否 enabled: true；
2. 权限模式是否在自动编辑模式（门卫的放行决策作用于"本来会询问"的请求）；
3. 查看 `~/.zcode/auto-review/review.log` 是否有记录——完全没记录说明 hook 没触发，
   去 设置 → 插件管理 → auto-review 详情页确认 hooks 已注册且可运行。

## 弹框提示"安全审查不可用…已转人工审查"？

安全子 agent 的 LLM 调用失败了（reason 里带具体原因）。常见：
- provider 是 OAuth 型（无静态 apiKey）→ `/auto-review set provider <API Key 型 provider>`
- 模型名不对 → `/auto-review set model <模型名>`
- 网络不通/超时 → 稍后重试或 `/auto-review set timeout_ms 45000`

这是**兜底行为不是故障**：审查不可用时一律转人工，不会放行。

## 每条命令都要等几秒？

安全子 agent 审查需要 1~5 秒。提速手段：
- 换快模型：`/auto-review set model glm-5.3-flash`
- 高频安全命令加白名单：`/danger-rules add allow '^ls\b' 'ls 白名单'`（跳过 LLM，零延迟）
- 相同命令默认有 1 小时缓存（`cache_ttl_seconds` 可调）

## 主 agent 说找不到 ctl.js？

插件更新后缓存目录版本号会变化，让主 agent 重新执行命令文档里的 find 定位即可；
若 find 结果为空，说明插件未安装/未启用，去 设置 → 插件管理 检查。

## 规则好像没生效？

- `/danger-rules test '<命令>'` 先验证正则是否命中；
- 规则按数组顺序匹配，前面更宽的规则（尤其 allow）可能抢先命中，`/danger-rules list` 检查顺序；
- 正则大小写不敏感、多行模式；`rm -rf /` 这类出厂规则勿随意删除。

## hook 输出 schema 校验失败（ZCode 日志里 hook 标记 failed）？

极少数情况下客户端严格 schema 与当前输出字段名不一致。插件把输出协议集中在
`src/decision.js` 单文件，并可临时切换风格验证：
设置环境变量 `AUTO_REVIEW_OUTPUT_STYLE=simple` 后观察，再按客户端文档修正字段名。

## 会把我的 API Key 记录到日志吗？

不会。apiKey 只在内存中拼请求头；日志、缓存、reason 中均不含密钥；
测试代码对配置 fixture 的密钥同样脱敏处理。
