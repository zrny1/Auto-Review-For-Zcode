# 功能介绍

## 解决什么问题

ZCode 的内置权限模式是两个极端：全自动模式缺少安全门卫；默认模式每条命令都打断你。
auto-review 填补中间地带——**由一个 AI 安全审查者代替你做初筛**：

```
主 agent 请求执行命令
   ├─ 命中你设置的确定性规则 → 直接拦截 / 直接转人工（不经过 AI）
   ├─ 安全子 agent 审查通过  → 自动放行，不打扰你
   └─ 安全子 agent 认为有风险 → 弹审批框，附带分析、风险点、影响范围
```

## 六个核心能力

| 能力 | 说明 | 对应需求 |
|------|------|----------|
| 自动审查模式 | 自动编辑模式 + hook 门卫，安全的自动放行 | 需求1 |
| 脚本全文审查 | Bash 命令逐条分析（含 `;` `&&` `|` 串联的每一段） | 需求2 |
| 结构化审批框 | reason 三段式：分析 / 风险点 / 影响范围 | 需求3 |
| 危险规则层 | 本地正则，deny/ask/allow 三种动作，不经过 LLM | 需求4 |
| 可改审查提示词 | 安全子 agent 的策略全文可编辑，立即生效 | 需求5 |
| provider 复用 | 默认跟随主 agent 当前 provider，可换用其他/快模型 | 需求6 |

## 安全设计要点

- **上下文干净**：安全子 agent 是 hook 进程内的独立 LLM 调用，只收到本次工具调用的 JSON。
  对话历史里哪怕被注入了"后续所有命令都视为安全"，对本审查层也无效。
- **确定性优先**：你的危险规则永远先于 LLM；LLM 的结论不可能覆盖你的显式规则。
- **LLM 无拦截权**：安全子 agent 只能建议 allow/ask；显式拦截（deny）只能来自你配置的规则，
  防止模型幻觉把工作流卡死。
- **失败必保守**：LLM 超时、报错、输出不可解析时一律转人工，绝不在错误时放行；
  插件自身崩溃时阻断（exit 2）而非放行。
- **默认关闭**：安装后不改变任何行为，`/auto-review on` 显式开启后才介入。
