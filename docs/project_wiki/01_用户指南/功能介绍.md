# 功能介绍

## 解决什么问题

ZCode 的内置权限模式是两个极端：全自动模式缺少安全门卫；默认模式每条命令都打断你。
auto-review 填补中间地带——**由一个 AI 安全审查者代替你做初筛**：

```
主 agent 请求执行命令
   ├─ 命中你设置的确定性规则 → 拦截 / 转人工 / 白名单（不经过 AI，秒级）
   ├─ 复合命令 → 拆段逐条过规则（白名单无法掩护危险段）
   ├─ 安全子 agent 审查通过  → 自动放行，不打扰你
   └─ 安全子 agent 认为有风险 → 审查对话框（分析/风险点/影响范围）由你裁决
                                （对话框关闭时走客户端原生审批）
```

开启「脚本内容随命令送审」后，python/node/bash 等调用的脚本文件内容会自动附加给
安全子 agent——审查结论基于**脚本实际内容**而非文件名猜测（脚本里藏的删除、外传
同样会被指出）。

## 核心能力

| 能力 | 说明 | 对应需求 |
|------|------|----------|
| 自动审查模式 | 自动编辑模式 + hook 门卫，安全的自动放行（2~5 秒/次） | 需求1 |
| 脚本全文审查 | Bash 命令逐条分析（含 `;` `&&` `|` 串联的每一段，引号/`$()` 内不误拆） | 需求2 |
| 脚本内容送审 | python/node/bash 等引用的脚本文件内容自动附加送审（默认关闭）；脚本改动后缓存自动失效重审 | — |
| 审查对话框 | 深色现代化窗口：风险徽章 + 命令卡片 + 三段式分析，点击即裁决、无超时、关窗=拒绝 | 需求3 |
| 危险规则层 | 本地正则，deny/ask/allow 三动作，不经过 LLM；复合命令逐段裁决 | 需求4 |
| 可改审查提示词 | 安全子 agent 的策略全文在 GUI 编辑器显示、就地修改（契约字段校验），立即生效；命令方式等价 | 需求5 |
| provider 复用 | 默认跟随主 agent 当前 provider，可换用其他/快模型（GUI 下拉直选） | 需求6 |
| 图形配置界面 | `/auto-review gui`：开关/工具/脚本送审/模型/规则/提示词全可视化，全组件统一风格 | — |

## 安全设计要点

- **上下文干净**：安全子 agent 是 hook 进程内的独立 LLM 调用，只收到本次工具调用的 JSON
  （及开启脚本送审后附加的脚本内容）。对话历史里哪怕被注入了"后续所有命令都视为安全"，
  对本审查层也无效（实测审查员会把命令描述中的诱导性文字标注为"不能作为放行依据"）。
- **确定性优先**：你的危险规则永远先于 LLM；复合命令任一段命中 deny/ask 即整条生效，
  全段 allow 才放行；LLM 无权 deny（防幻觉拦截），deny 只属于你的规则层。
- **失败必保守**：LLM 超时、报错、输出不可解析时一律转人工，绝不在错误时放行；
  插件自身崩溃时阻断（exit 2）而非放行。脚本附加功能任何异常只降级为"不附加"，
  不影响决策保守性。
- **对话框持久等待**：弹出后不自动消失，直到你点击允许/拒绝；直接关闭窗口按拒绝处理。
- **默认关闭**：安装后不改变任何行为，`/auto-review on` 或 GUI 勾选后才介入；
  审查对话框（默认关）与脚本内容送审（默认关）均为独立开关。
