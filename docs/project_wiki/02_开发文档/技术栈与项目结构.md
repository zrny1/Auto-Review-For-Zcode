# 技术栈与项目结构

## 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 运行时 | Node.js ≥ 18 | 仅内置模块（fs/path/crypto/fetch/AbortController），零第三方依赖 |
| 插件接口 | ZCode 插件体系 | `.zcode-plugin/plugin.json` 清单；贡献 hooks + commands |
| hook 协议 | PreToolUse | stdin 收 hook JSON，stdout 输出 `hookSpecificOutput.permissionDecision` |
| LLM 协议 | Anthropic Messages / OpenAI Chat Completions | 按 provider 的 kind 二选一，内置 fetch 直连 |
| 测试 | node:test + 子进程冒烟 | 无测试框架依赖 |

## 目录结构

```
DemoSuperVisionForZcode/            # 仓库根 = 插件根
├── .zcode-plugin/plugin.json       # 清单（commands + hooks）
├── hooks/hooks.json                # PreToolUse 注册（process 型，node 启动）
├── commands/                       # 三个斜杠命令（指导主 agent 调 ctl.js）
│   ├── auto-review.md              # 总控：状态/开关/set
│   ├── danger-rules.md             # 危险规则 CRUD + test
│   └── security-prompt.md          # 提示词 show/edit/reset
├── src/                            # 核心源码（7 个模块，全部 ES Module）
│   ├── common.js                   # 路径常量/日志轮转/原子写/JSON 防御读
│   ├── settings.js                 # 配置与规则加载（回落出厂默认+类型钳制）
│   ├── provider.js                 # ZCode 配置解析 + 双协议 LLM 调用
│   ├── reviewer.js                 # 决策管线（六层编排）
│   ├── decision.js                 # hook 输出协议封装（唯一客户端耦合点）
│   ├── hook_main.js                # PreToolUse 入口
│   └── ctl.js                      # 控制 CLI（命令的唯一操作入口）
├── config/                         # 出厂默认（settings/14条规则/提示词）
├── scripts/                        # 测试（单测/冒烟/真实LLM冒烟）
└── docs/                           # 需求、方案、wiki、日志、过程归档
```

## 运行时数据目录（不在仓库内）

`~/.zcode/auto-review/`：settings.json / danger_rules.json / security_prompt.md / cache.json / review.log。
由 hook 进程与主 agent（经 ctl.js）共同读写；测试用 `AUTO_REVIEW_DATA_DIR` 重定向隔离。
