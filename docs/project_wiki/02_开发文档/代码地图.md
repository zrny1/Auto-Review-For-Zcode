# 代码地图

> 模块 → 文件 → 核心函数 → 职责。文件头均有统一格式注释。

## src/common.js —— 配置中心

| 导出 | 职责 |
|------|------|
| `g_data_dir`（内部） | 数据目录：`AUTO_REVIEW_DATA_DIR` 环境变量优先，否则 `~/.zcode/auto-review` |
| `getDataDir()` | 返回数据目录并按需创建 |
| `logWrite(level, module, msg)` | 统一日志（时间戳[级别][模块]），512KB 轮转，失败静默 |
| `readJsonFile(path, fallback, module)` | 防御式 JSON 读取，ENOENT 静默回落 |
| `writeFileAtomic(path, content)` | 临时文件 + rename 原子写 |
| `*_FILE` 常量 | 数据目录与出厂默认的全部路径 |

## src/settings.js —— 配置加载

| 导出 | 职责 |
|------|------|
| `loadSettings()` | 出厂默认 + 数据目录覆盖（类型校验）+ 数值钳制（timeout 5~45s 等）；`dialog_on_ask` 默认 false |
| `saveSettings(s)` | 原子写 settings.json |
| `loadDangerRules()` | 规则编译（im 标志）；非法正则跳过并 WARN，序号保持原始位置 |
| `loadRawDangerRules()` / `saveDangerRules(r)` | 原始规则表读写（ctl/GUI 用） |
| `loadSecurityPrompt()` | 数据目录提示词 → 出厂默认 → 最小兜底串 |

## src/provider.js —— provider 解析与调用

| 导出 | 职责 |
|------|------|
| `resolveProvider(settings)` | `~/.zcode/v2/config.json`（回退 cli）解析：显式指定（兼容 `builtin:` 前缀）或首个 enabled；apiKey/baseURL/model 校验 |
| `callLlm(info, system, user)` | anthropic（`/v1/messages`，**thinking 显式 disabled**，max_tokens 2048）或 openai（`/chat/completions`）；AbortController 超时；单次不重试 |
| `ProviderError` / `LlmError` | 面向日志的错误类型（消息不含密钥） |

## src/reviewer.js —— 决策管线

| 导出 | 职责 |
|------|------|
| `reviewToolUse(hook_input)` | **主入口**，编排 + 兜底，保证不抛异常 |
| `normalizeToolName()` | ApplyPatch→Write 等别名归一 |
| `buildRuleText()` | Bash→命令全文；Write/Edit→目标路径；空输入不送审 |
| `matchDangerRules(text)` | 全文规则层：首个命中生效；**allow 禁止作用于复合命令全文** |
| `splitTopLevelCommands(text)` | 顶层分割（`;` `&&` `\|\|` `\|` 换行），引号/`$()`/反引号内不切分 |
| `matchCompoundRules(text)` | 复合逐段：任一段 deny→整体拦截、ask→整体转人工、全 allow→放行、混合→null 降级 LLM |
| `extractScriptRefs(command)` | 提取命令引用的脚本路径（0.2.3）：解释器/`-File`/`/c`/裸路径，内联与模块模式排除，引号内空格不切分 |
| `collectScriptAttachments(command, cwd, settings)` | 读取脚本文件构造送审附件（0.2.3）：截断/二进制/缺失/数量上限防御，异常只降级为不附加 |
| `hashAttachments(attachments)` | 附件摘要（路径+内容 sha256），参与缓存键加盐；空附件返回空串 |
| `buildReviewPayload(tool, input, max, attachments)` | 送审载荷：工具 JSON 截断 + 可选脚本附件块（独立预算） |
| `computeCacheKey()` / `readCachedDecision()` / `writeCachedDecision()` | 稳定序列化（键排序）sha256 键 + 附件摘要加盐（无附件与旧键一致）；TTL 惰性清理；上限 500 条 |
| `extractJsonObject()` | 平衡花括号扫描（字符串内 `}` 不截断），容忍围栏 |
| `parseVerdict()` | 输出契约解析；**deny 收敛为 ask**；非法输出抛错 |
| `formatVerdictReason()` | 三段式 reason：风险级别+分析 / 风险点列表 / 影响范围 |

管线顺序：①开关 → ②工具过滤 → ③规则层 → ③'复合逐段 → ③''会话白名单 →
③.5脚本附加（inspect_scripts）→ ④缓存 → ⑤LLM → ⑥兜底 ask。
所有 ask 决策附带 `additionalContext`（同文本，送主 agent 上下文）。

## src/decision.js —— 输出协议（唯一客户端耦合点）

| 导出 | 职责 |
|------|------|
| `emitDecision({action, reason, additionalContext})` | pass→空输出 exit 0；allow/ask/deny→`{hookSpecificOutput:{hookEventName,permissionDecision,permissionDecisionReason,additionalContext?}}`；`AUTO_REVIEW_OUTPUT_STYLE=simple` 可切换 |
| `emitCrash(msg)` | 内部崩溃最终防线：stderr + exit 2（阻断） |

## src/hook_main.js —— hook 入口

`readStdinAll()` 全量读 stdin → JSON 容错（空/非法→pass）→ `reviewToolUse()` →
**对话框裁决映射**（`dialog_on_ask` 开启且非远程标记时）：`askUserViaDialog()` 返回
allow→改判 allow / deny→改判 deny / timeout→保持 ask 回落原生审批；
`AUTO_REVIEW_DISABLE_DIALOG` 跳过（测试用）。未捕获异常 → 日志 + `emitCrash`。

## src/dialog.js —— 审查对话框

| 导出 | 职责 |
|------|------|
| `parseReasonForDialog(reason)` | reason → {risk, analysis, risks, scope, plain} 结构化 |
| `askUserViaDialog(title, command, reason)` | 阻塞弹出 WinForms 深色窗口（`-STA`）；无超时（24h 硬上限）；关窗=拒绝；ShowWindow 强制可见（对抗 windowsHide 的 SW_HIDE） |
| `THEME` / `DIALOG_PS_SCRIPT` | 主题常量与 PS 脚本（供 gui.js 复用与校验器检查） |

## src/gui.js —— 图形配置界面

| 导出 | 职责 |
|------|------|
| `launchSettingsGui()` | 阻塞弹出设置窗口；保存写 settings/danger_rules（单元素数组手工包装） |
| `GUI_PS_SCRIPT` | 扁平分区布局；自绘勾选框（New-Check）/下拉（Theme-Combo）/列表（DrawItem）；"跟随主 agent"时模型下拉用启用 provider 填充 |

## src/ctl.js —— 控制 CLI

`init / status / set <k> <v> / rules list|add|remove|test / prompt show|path|reset / gui`；
键白名单（含 dialog_on_ask）+ 类型/区间校验 + 正则自校验；错误走 stderr + exit 1。
