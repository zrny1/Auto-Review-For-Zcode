# 扩展点与接口

> 面向二次开发者：不改核心管线就能扩展的位置。

## 环境变量（测试与调试钩子）

| 变量 | 作用 |
|------|------|
| `AUTO_REVIEW_DATA_DIR` | 重定向数据目录（单测/冒烟的隔离基础） |
| `AUTO_REVIEW_ZCODE_CONFIG` | 替换 ZCode provider 表配置文件路径（provider fixture） |
| `AUTO_REVIEW_PROVIDER_CONFIG` | 替换 `~/.zcode/v2/provider_config.json` 规则文件路径（0.2.4；设置 `AUTO_REVIEW_ZCODE_CONFIG` 后默认不读真实规则文件，保持测试隔离） |
| `AUTO_REVIEW_OUTPUT_STYLE` | `simple` 时输出 `{decision, reason}` 简化协议（集成期排查） |
| `AUTO_REVIEW_DISABLE_DIALOG` | 置 1 时跳过审查对话框（测试环境防真实弹窗） |

## 出厂默认配置

`config/` 三份文件是所有运行时数据的回落源：
改 `default_danger_rules.json` = 改内置规则基线；改 `default_security_prompt.md` = 改默认审查策略。
数据目录同名文件始终优先——升级插件不会覆盖用户自定义。

## 扩展审查工具

1. `hooks.json` 的 matcher 已覆盖 `Bash|Write|Edit|ApplyPatch`，新增工具需先扩 matcher；
2. `reviewer.js` 的 `buildRuleText()` 加新工具的送审文本分支；
3. `reviewer.js` 的 `TOOL_ALIASES` 加别名（如有）；
4. 用户侧 `/auto-review set review_tools '["Bash","Write","MCP__x__y"]'` 即可启用（GUI 勾选同理）。

## 自定义 LLM 输出契约

`reviewer.js` 的 `parseVerdict()` 是唯一解析点。若提示词实验引入新字段（如 `suggestion`），
在此归一化并在 `formatVerdictReason()` 拼装即可，管线其余部分无感。

## 接入其他客户端/hook 事件

`decision.js` 集中了全部协议细节。接 PostToolUse 等其他事件时：
复制该文件模式，按事件 schema 输出；管线 `reviewer.js` 本身与事件类型无关。

**PermissionRequest 与 PreToolUse 的选型结论**（客户端 3.12.3 逆向实证，二次开发必读）：

- `PermissionRequest` **仅在权限决策为"要弹框询问"时触发**（与用户响应竞速），自动编辑模式下
  大多数调用不弹框——迁过去会失去"安全命令自动放行"能力；
- 其输出 schema 只有 `decision: {behavior: allow(+permissionUpdates) / deny(+interrupt,message)}`，
  **没有 ask 态、没有 reason 通道、不支持 additionalContext**——无法把审查分析送进审批框；
- `PreToolUse` 在权限评估**之前**运行：ask 升级路径会把 `permissionDecisionReason` 送进
  原生审批框（本地与远程同源）；即使用户点了"总是允许"加了规则，hook 的 ask 仍能把后续
  同类调用升级回询问，危险命令审查不会被 always-allow 旁路；
- 结论：**审查决策保持在 PreToolUse**；PermissionRequest 仅在需要"用户已被询问时再决策"
  或 allow+permissionUpdates 原生化"会话级放行"时作为补充注册。

## GUI 相关（PowerShell WinForms）

- 主题常量集中在 `dialog.js` 的 `THEME`（gui.js 复用），改配色/圆角一处生效；
- `scripts/validate_ps.js`：改 PS 脚本后先跑语法校验（BOM 处理已内置）；
- `scripts/probe_window.ps1`：按标题探测窗口 hwnd/可见性/坐标，排查"窗口不见"类问题。

## 调试方法

- 单测：`node --test scripts/unit_tests.test.js`
- 冒烟（不触网、不弹窗）：`node scripts/smoke_test.js`
- PS 语法校验：`node scripts/validate_ps.js`
- 真实链路：`node scripts/llm_smoke.js`（2 次真实调用）
- LLM 响应诊断（thinking/token 观测）：`node scripts/debug_llm_response.js`
- 手动喂输入：`echo '{"tool_name":"Bash","tool_input":{"command":"ls"}}' | AUTO_REVIEW_DATA_DIR=/tmp/ar node src/hook_main.js`
- 决策日志：`~/.zcode/auto-review/review.log`；hook 执行记录：ZCode 日志（含超时/失败/schema 校验结果）

## 已知坑（本项目建设中实测踩过）

| 坑 | 现象 | 规避 |
|----|------|------|
| PS 事件处理器作用域隔离 | Tick 回调取不到外层局部变量（NULL 方法调用），异常框每秒弹出 | 状态存 `$this.Tag` / `$script:` 作用域；handler 只调脚本级函数 |
| spawnSync 的 windowsHide | STARTUPINFO 携带 SW_HIDE，某些进程链上 ShowDialog 不覆盖，窗口建成但 visible=False | ShowDialog 前 P/Invoke `ShowWindow(SW_SHOW)` |
| GLM 混合推理 thinking | 默认长思考吃掉 max_tokens 导致正文为空、耗时 16s 级 | anthropic 请求显式 `thinking:{type:"disabled"}` |
| New-Object 带算术的参数 | `Size($w-30,24)` 在参数数组上下文解析异常 | 先算入临时变量再传 |
| bash→powershell 引号 | `$_` 被展开、转义被剥离 | PS 逻辑写 .ps1 文件执行，动态内容走环境变量 |
| hook 配置会话期绑定 | 改 hooks.json（如 timeoutMs）不热加载 | 新会话生效 |
| 插件缓存仅启动时同步 | 改了插件源码但 hook/命令仍跑旧逻辑（本地 marketplace 的运行缓存在 ZCode 启动时才从项目根同步） | 重启 ZCode；或临时手动同步 `~/.zcode/cli/plugins/cache/<市场名>/auto-review/`（src/commands/config/hooks/清单），验证时注意区分"探针脚本写的日志"与"hook 写的日志" |
| PS5.1 读无 BOM 的 UTF-8 | 独立 .ps1 文件含中文时按 ANSI 解析，字符串边界错乱、语法报错 | .ps1 文件带 UTF-8 BOM；或像插件正式脚本那样经 `-Command` 字符串传递 |
