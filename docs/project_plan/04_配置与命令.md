# 04 配置与命令

## 职责

运行时配置的数据模型、数据目录布局、出厂默认回落机制，以及三个斜杠命令的行为定义（需求4/5/6 的用户入口）。

## 数据目录

统一为 `~/.zcode/auto-review/`（跨平台 `os.homedir()` 计算），hook 进程与命令（主 agent）都能确定性地推出该路径。
不使用 `${ZCODE_PLUGIN_DATA}`：其真实值无法在开发期验证，而主 agent 侧执行命令时也未必拿到该变量，
统一固定路径可避免两侧不一致。目录内容：

```
~/.zcode/auto-review/
├── settings.json         # 运行时配置（命令可改）
├── danger_rules.json     # 危险规则表（命令可改）
├── security_prompt.md    # 安全子 agent 提示词（命令可改）
├── cache.json            # 审查缓存（自动维护）
└── review.log            # 审查日志（自动轮转）
```

加载顺序：数据目录文件存在 → 使用之；否则回落到插件内 `config/` 出厂默认（只读），并在首次写操作时把默认落盘到数据目录。

## settings.json 数据模型

```json
{
  "enabled": false,
  "review_tools": ["Bash"],
  "provider": "",
  "model": "",
  "timeout_ms": 30000,
  "cache_ttl_seconds": 3600,
  "max_payload_chars": 8000
}
```

| 字段 | 说明 |
|------|------|
| enabled | 总开关。默认 false——装上不立即改变行为，用户显式打开 |
| review_tools | 参与审查的工具名列表。默认只审 Bash（自动编辑模式下 Write/Edit 本就自动放行，属"权限内"） |
| provider | 空 = 跟随主 agent 当前启用的 provider；非空 = 指定其他 provider（需求6） |
| model | 空 = 该 provider 的第一个模型；推荐配置 flash 级快模型降延迟 |
| timeout_ms | LLM 调用超时，钳制在 [5000, 45000] |
| cache_ttl_seconds | 缓存有效期 |
| max_payload_chars | 送审载荷截断长度 |

## danger_rules.json 数据模型（需求4）

```json
[
  {
    "pattern": "rm\\s+(-[a-zA-Z]*r[a-zA-Z]*f[a-zA-Z]*|-[a-zA-Z]*f[a-zA-Z]*r[a-zA-Z]*)\\s+(/|~|\\$HOME|C:\\\\)",
    "action": "deny",
    "description": "递归强制删除根/家目录/盘符"
  },
  {
    "pattern": "git\\s+push\\s+.+--force",
    "action": "ask",
    "description": "强推可能覆盖远程历史"
  }
]
```

- `pattern`：JavaScript 正则源文本（`new RegExp(pattern)`），**不区分大小写**（命令名在 Windows 上大小写不定），多行匹配
- `action`：`deny`（拦截）| `ask`（转人工）| `allow`（白名单，跳过 LLM）
- `description`：展示在审批框 reason 与日志中，说明为什么危险
- 非法 pattern（编译失败）在加载时跳过并 WARN 日志，不影响其他规则
- 出厂默认内置约 10 条高危规则（删除根目录、磁盘格式化、注册表写、强推、curl 管道执行、修改 shell 配置、结束进程组、sudo 提权等）

匹配对象：`Bash` 匹配命令全文；`Write/Edit` 匹配目标路径。

## security_prompt.md（需求5）

出厂默认提示词定义安全子 agent 的角色、审查维度、输出契约与裁量边界：

- 角色：最小权限保守审查员，证据不足倾向 ask
- 审查维度：破坏性（删除/覆盖/格式化）、不可逆性（git force push、迁移）、数据外发（网络上传、curl POST）、提权（sudo/管理员）、范围逃逸（越出工作目录写系统路径）、隐蔽执行（管道执行远程脚本、混淆命令）
- 输出契约：只输出 02 方案定义的 JSON，无其他文本
- 裁量边界：只判 allow/ask，不判 deny（拦截特权属于用户规则层）

用户通过 `/security-prompt` 命令查看与修改全文，修改立即生效（每次审查前现读文件）。

## 斜杠命令（commands/）

命令是指导主 agent 操作数据目录的 markdown 文档（frontmatter + 指令正文），
路径统一写 `~/.zcode/auto-review/`（主 agent 在 Git Bash 下 ~ 可用）。

### /auto-review（总控）

| 用法 | 行为 |
|------|------|
| `/auto-review` | 读取并汇报：开关状态、review_tools、provider/model、规则条数、提示词是否自定义 |
| `/auto-review on` / `off` | 置位 settings.json 的 enabled（原子写：临时文件 + rename） |
| `/auto-review set <key> <value>` | 修改 settings.json 指定字段，值按 JSON 解析，非法键/值拒绝并提示合法范围 |

### /danger-rules（需求4入口）

| 用法 | 行为 |
|------|------|
| `/danger-rules list` | 表格列出全部规则：序号、动作、描述、正则 |
| `/danger-rules add <action> <pattern> <description>` | 追加规则，先 `new RegExp` 自校验合法性再落盘 |
| `/danger-rules remove <序号>` | 按序号删除 |
| `/danger-rules test <命令文本>` | 对给定命令跑一遍规则层，报告命中情况（不调 LLM） |

### /security-prompt（需求5入口）

| 用法 | 行为 |
|------|------|
| `/security-prompt show` | 输出当前提示词全文（数据目录的，回落出厂默认） |
| `/security-prompt edit <要求>` | 按用户自然语言要求改写提示词后落盘（先 show diff 再写入） |
| `/security-prompt reset` | 恢复出厂默认提示词 |
