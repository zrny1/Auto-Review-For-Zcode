# process

## 本轮需求/背景

用户提出两个问题（0.2.3 周期）：

1. 安全子 agent 的安全策略提示词应当在 GUI 中显示，并且可以修改——此前只能用
   `/security-prompt path` 拿路径后由主 agent 或外部编辑器改文件，GUI 无提示词入口；
2. 安全子 agent 是否可以查看文件，对运行脚本的命令做进一步审查——安全子 agent 是
   单轮无工具的 LLM 调用，只收到命令文本，`python deploy.py` 这类命令看不到脚本内容，
   只能凭文件名猜测（测试中预期行为即"执行外部脚本，内容未随调用提供无法确认行为"转人工）。

方案规划（计划模式）确认两个产品决策：提示词编辑采用独立编辑器窗口（设置窗口加分区
入口，主窗口布局基本不动、编辑空间大，复用"添加危险规则"子对话框模式）；
`inspect_scripts` 默认关闭（用户显式开启；脚本内容与命令文本发同一 provider，无新信任域）。

## 预期修改计划

- 需求 2 核心：reviewer.js 脚本引用提取 + 文件读取附加 + 载荷附件块 + 缓存键附件加盐
  （无附件与旧键兼容）；settings 新键 inspect_scripts / script_max_bytes（钳制
  1000~100000）全链路（default_settings / settings.js / ctl.js set·status）
- 需求 1：gui.js 新增提示词分区 + 独立编辑器子窗口（显示全文/编辑/恢复出厂/
  契约字段校验/UTF-8 无 BOM 落盘立即生效）+ 脚本送审勾选与上限输入
- 出厂提示词补充"脚本附件块"审查对象说明
- 测试：单元 +6、场景 +4（含缓存加盐内容变化重审）
- 文档治理：方案 02/04、可执行计划阶段九、命令文档、README、wiki、变更记录、版本号 0.2.3

## 实际修改步骤

- config/default_settings.json：+inspect_scripts(默认 false)、+script_max_bytes(默认 16000)
- src/reviewer.js：
  - 常量 MAX_SCRIPT_FILES=3 / SCRIPT_EXTENSIONS(13 种脚本扩展名) / SCRIPT_INLINE_FLAGS
    (-c/-e/-m/--command/--eval/--module) / SCRIPT_INTERPRETERS(13 个解释器)
  - 新函数 tokenizeSegment（引号内空格不切分）、isScriptPath、extractRefFromSegment
    （解释器跳选项取路径、powershell -File / cmd /c·/k 特判、段首裸脚本路径；
    内联/模块模式整段放弃）、extractScriptRefs（复用 splitTopLevelCommands 逐段提取、
    去重保序）、expandTilde、collectScriptAttachments（cwd 解析、stat 普通文件、
    超限只读前 N 字节截断标注、前 8K 含 NUL 判二进制跳过、超 3 个截断、失败附注且
    详细原因只进日志；整体异常降级为不附加）、hashAttachments（路径+内容 sha256 拼接）
  - buildReviewPayload 加 attachments 参数：附件块独立预算追加（含"结论必须结合脚本
    实际内容"标题、逐文件路径/大小/围栏、附注行）；无附件格式与旧版逐字节一致
  - computeCacheKey 加可选 extra_salt：非空才拼接，无附件与旧键完全一致（历史缓存/
    会话白名单条目兼容）
  - runLlmReview 加 attachments 参数：载荷与缓存键同用附件摘要；llm 日志行附 scripts=N
  - 管线接线：会话白名单之后、缓存之前做附件收集（白名单键保持原始键——用户批准的是
    命令本身；缓存键加盐——脚本内容变化自动失效重审）
- src/settings.js：script_max_bytes 钳制 [1000,100000]（常量 SCRIPT_BYTES_MIN/MAX）
- src/ctl.js：SETTABLE_KEYS +inspect_scripts/script_max_bytes、NUMBER_RANGES 补区间、
  status 输出新键
- config/default_security_prompt.md：审查对象节补脚本附件块说明与裁量要求
  （未能附上的仍按"内容不可见"从严）
- src/gui.js：窗口 760×760→760×876（模型区起整体下移 32px，底部按钮区下移）；
  审查范围区 +「脚本内容随命令送审」自绘勾选 +「上限(字节)」输入；危险规则区后新增
  「安全策略提示词」分区（状态标签 出厂默认/已自定义 + 打开提示词编辑器按钮）；
  提示词编辑器子窗口（820×664，Consolas 多行双向滚动编辑框、恢复出厂/关闭/保存，
  保存校验：非空 + 契约五字段缺失 YesNo 警告、数据目录缺失先创建、UTF8Encoding($false)
  写 AR_PROMPT_FILE、成功后刷新主窗口状态标签）；数据加载由"整体替换"改逐键合并

## 验证结果

- 离线全绿：单元 27/27（原 21 + 新 6）、场景 20/20（原 16 + 新 4）、冒烟 14 断言组、
  node --check 全部 src、validate_ps 双脚本语法通过
- ctl 新键实测（隔离数据目录）：set inspect_scripts true ✓、set script_max_bytes 50→
  钳制 1000、999999→钳制 100000、status 展示"inspect_scripts: true（单文件上限 100000 字节）"✓
- PS 逐键合并逻辑独立验证：旧版 settings.json（缺 inspect_scripts/script_max_bytes）
  合并后新键回填默认值（$null 防御通过）、旧值仍正常覆盖 ✓
- GUI 实机验证：`node src/ctl.js gui`（隔离数据目录）窗口正常显示（探测器确认
  visible=True、760×876）、正常关闭 exit 0、关闭后 status 输出新键 ✓
- 实机意外验证：开发会话中本插件危险规则 #11 拦截含 `Remove-Item -Recurse -Force` 的
  验证命令并弹对话框、用户拒绝生效（规则层 + 对话框链路在工作）
