# 项目需求文档（只读）

> 本文档为项目需求的唯一权威来源，项目初始化时固化，此后不允许修改。

## 项目背景

ZCode 当前有四种内置权限模式。全自动模式缺少安全门卫、默认模式打断过多，缺少一个"中间地带"：
由一个上下文干净的 AI 安全审查者代替用户做初筛，安全的操作自动放行，不安全的才升级给用户。

本项目开发一个 ZCode 插件 `auto-review`（自动审查权限），填补该空白。

## 功能需求（用户原始需求，逐条固化）

1. 在现有四个权限模式的基础上新增"自动审查"权限：
   - 主 agent 的权限默认为自动编辑模式；
   - 增加一个上下文干净的安全子 agent，负责审查主 agent 在权限外的请求；
   - 安全的请求自动通过，不安全的请求转发给用户审查。
2. 对运行脚本的请求，安全子 agent 审查脚本本身是否安全。
3. 用户看到的请求框新增安全子 agent 对指令的分析、风险点和影响范围。
4. 允许用户快捷地设置危险指令，通过 hook 机制自动拦截或转发给用户审查（此机制不经过安全子 agent）。
5. 允许用户修改安全子 agent 的提示词，来调整安全子 agent 的审查策略。
6. 复用 ZCode 当前的 provider 作为安全子 agent 的 provider，允许与主 agent 使用不同的 provider。

## 技术边界（调研结论，作为需求约束）

- 插件不能修改客户端内置的权限模式枚举，"自动审查"通过"内置自动编辑模式 + PreToolUse hook 门卫"模拟实现；
- `PreToolUse` hook 可返回 `allow` / `ask` / `deny` 权限决策，`ask` 附带的 reason 会展示在用户审批框中；
- 安全子 agent 实现为 hook 进程内调用的 LLM（只接收本次工具调用的 JSON，不接触对话上下文，天然免疫对话内提示注入）；
- provider 信息从 ZCode 配置文件读取（`~/.zcode/v2/config.json`），支持 Anthropic 兼容与 OpenAI 兼容两种协议。

## 非功能需求

- 失败必须兜底：LLM 调用超时、报错、输出不可解析时，一律返回 `ask`（转人工审查），绝不在错误时自动放行；
- 危险规则层为确定性第一层（正则匹配，不经过 LLM），命中即决策；
- 相同工具调用的审查结论支持缓存，降低延迟与 token 消耗；
- 核心脚本零第三方依赖（仅 Node.js 内置模块），无需 npm install 即可运行。
